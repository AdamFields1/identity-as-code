# stacks/aws-identity-center

The deployable unit for one IAM Identity Center instance. It composes two modules,
in order, into one plan and one state file:

1. `permission-set` creates the permission sets and everything attached to them.
2. `account-assignment` creates one assignment per convention-named group.

Tenant cells under `tenants/aws/<partition>/aws-identity-center/` point at this
stack and provide values only: the permission set definitions and a list of group
names. There is one cell per Identity Center instance: `commercial` and
`govcloud`. They are different partitions, different organizations, different
state buckets, and different OIDC roles, and the same stack deploys to both
because nothing in it names a partition. See
[ADR 0009](../../docs/adr/0009-partition-aware-aws-cells.md).

## The model

```
AWS-<PARTITION>-<accountId>-<PermissionSetName>        (an Entra security group)
        |                                    |
        | assigned to the partition's        | SCIM provisions it into the
        | gallery app in Entra               | identity store, same name
        v                                    v
   stacks/entra-aws-federation        this stack: parse the name, assign
                                      PermissionSetName in accountId
```

The group name is the assignment. `AWS-COM-111111111111-ReadOnly` is a group whose
members get the `ReadOnly` permission set in account `111111111111` of the
commercial instance, and that is all the cell has to say about it. Membership
lives in Entra ID (with PIM for groups where activation should be just in time),
SCIM carries it into the identity store, and this stack grants the permission
set. Nobody is assigned as a user, and no cell contains an ID other than the
account ID the convention carries. See
[ADR 0008](../../docs/adr/0008-entra-id-as-the-identity-source-for-aws.md).

## Why one stack

An assignment references a permission set ARN, so Terraform creates the set first
and deletes the assignment first. Splitting them into two state files would make
"remove this permission set" a two-release change and would leave a window where
the set is gone and the assignment still points at it. The Azure side splits
definitions from assignments (ADR 0005) because custom role definitions and PIM
eligibilities have different owners and cadences; here a permission set and the
groups that carry its name are reviewed by the same people at the same time, so
one stack is the right shape.

## What this stack refuses

- A group name that does not match `^AWS-(GOV|COM)-[0-9]{12}-[A-Za-z0-9]+$`.
- A group whose `PermissionSetName` is not a permission set defined in the same
  cell (checked in the stack, so the error names the cell, and again in the
  module).
- A group for the other partition. The module reads the partition from
  `data.aws_partition` and a `GOV` group in the commercial cell fails the plan.
- A permission set name with characters the convention cannot carry.
- A user principal. There is no input for one.
- A policy ARN where a policy name is expected, and a session duration outside
  PT1H to PT12H.

## Provider configuration

`versions.tf` declares `required_providers` only. The `provider "aws"` block is
generated by Terragrunt (`tenants/aws/root.hcl`) with `region = var.region` and an
optional `assume_role` from `TG_AWS_ROLE_ARN`. In CI the credentials come from
GitHub OIDC through `aws-actions/configure-aws-credentials`; locally they come
from an SSO session or a profile. Nothing is typed into a cell.

The identity running the plan needs read access to the instance, its permission
sets, and the identity store (`sso:Describe*`, `sso:List*`,
`identitystore:GetGroupId`). Apply additionally needs `sso:CreatePermissionSet`,
the attachment and provisioning actions, and `sso:CreateAccountAssignment`. Run
it in the Identity Center delegated administrator account, not the management
account. No AWS Organizations permission is required; the account ID comes from
the group name.

## Standalone use without Terragrunt

```hcl
provider "aws" {
  region = "us-east-1"
}

module "aws_identity_center" {
  source = "./stacks/aws-identity-center"

  region = "us-east-1"

  permission_sets = {
    read-only = {
      name                 = "ReadOnly"
      session_duration     = "PT4H"
      aws_managed_policies = ["ReadOnlyAccess"]
    }
  }

  group_display_names = [
    "AWS-COM-111111111111-ReadOnly",
    "AWS-COM-222222222222-ReadOnly",
  ]
}
```

## Inputs

| Name | Type | Description |
|------|------|-------------|
| `region` | `string` | Region of the Identity Center instance. Selects the partition. |
| `permission_sets` | `map(object)` | Permission sets keyed by logical name. Names are letters and digits. |
| `group_display_names` | `list(string)` | Convention-named groups, one assignment each. |

## Outputs

| Name | Description |
|------|-------------|
| `instance_arn` | ARN of the instance. |
| `identity_store_id` | Identity store ID, the SCIM target. |
| `partition` | `aws` or `aws-us-gov`. |
| `permission_sets` | Key to `{ name, arn, session_duration }`. |
| `assignments` | Group name to the resolved assignment. |
| `group_ids` | Group name to identity store group ID. |
