# stacks/entra-app-registrations

The deployable unit for application onboarding in an Entra tenant. It composes two
modules into one plan and one state file:

1. `security-group` creates the access groups that will govern the applications.
2. `app-registration` creates the registrations, their service principals, their
   federated identity credentials, and any enforced Microsoft Graph grants.

Tenant cells under `tenants/azure/<tenant>/entra-app-registrations/` point at this
stack and provide values only. In this repository only `corp` has such a cell:
application onboarding is confined to the corporate tenant, and the subsidiary
consumes those applications as a multi-tenant audience rather than registering its
own.

## What this stack does not manage

- **Client secrets.** There is no `azuread_application_password` anywhere in the
  module. Workload identity is federated (GitHub OIDC). A secret added in the portal
  is reported by `scripts/Export-EntraDrift.ps1`.
- **Post-provisioning edits by owners.** Redirect URIs, optional claims, branding,
  tags, and owners are set at creation and then ignored. Terraform is the inventory
  and guardrail; owners keep day-to-day control. See
  [ADR 0006](../../docs/adr/0006-terraform-as-inventory-and-guardrail.md).
- **User and group assignment to enterprise applications, and Azure RBAC for the
  service principals.** The first belongs to the application owner, the second to
  the subscription code that owns the resources being accessed.

## Provider configuration

`versions.tf` declares `required_providers` only. The `provider "azuread"` and
`provider "azurerm"` blocks are generated by Terragrunt (`tenants/azure/root.hcl`),
which supplies `tenant_id` and `subscription_id` from `ARM_TENANT_ID` and
`ARM_SUBSCRIPTION_ID` so no tenant cell contains a GUID. Both providers
authenticate with OIDC. `subscription_id` is accepted but unused by this
Entra-only stack.

## Standalone use without Terragrunt

```hcl
provider "azuread" {
  tenant_id = "00000000-0000-0000-0000-000000000000"
  use_oidc  = true
}

module "entra_app_registrations" {
  source = "./stacks/entra-app-registrations"

  tenant_id = "00000000-0000-0000-0000-000000000000"

  security_groups = {
    payroll-api-users = {
      display_name = "APP Payroll API Users"
      owners       = ["app.owner@corp.example.com"]
    }
  }

  applications = {
    payroll-api = {
      display_name    = "Payroll API"
      owners          = ["app.owner@corp.example.com"]
      identifier_uris = ["api://payroll-api"]

      required_resource_access = {
        MicrosoftGraph = {
          application = ["User.Read.All"]
          delegated   = ["User.Read"]
        }
      }

      enforced_graph_app_roles = ["User.Read.All"]

      federated_credentials = {
        github-prod = {
          display_name = "GitHub Actions (prod)"
          subject      = "repo:example-org/payroll-api:environment:prod"
        }
      }
    }
  }
}
```

## Adopting existing registrations

1. Run `scripts/Export-EntraDrift.ps1` against the tenant with the tenant cell's
   `terragrunt.hcl` as the managed-names source. It writes a drift report, an
   `imports.tf`, and a `values.skeleton.hcl`.
2. Paste the skeleton entries you intend to manage into the tenant cell.
3. Drop `imports.tf` beside the tenant `terragrunt.hcl`. `root.hcl` picks it up.
4. Plan until it shows 0 to add, 0 to change, 0 to destroy (`tests/README.md`).
5. Apply, then delete `imports.tf`.

## Inputs

| Name | Type | Description |
|------|------|-------------|
| `tenant_id` | `string` | Entra tenant ID. |
| `subscription_id` | `string` | Accepted for the generated azurerm provider; unused here. |
| `security_groups` | `map(object)` | Access groups keyed by logical name. |
| `applications` | `map(object)` | Registrations keyed by logical name. |

## Outputs

| Name | Description |
|------|-------------|
| `group_ids` | Group key to object ID. |
| `applications` | Application key to `{ object_id, client_id, display_name, service_principal_object_id }`. |
| `client_ids` | Application key to client ID. |
| `federated_credential_ids` | `app/credential` key to credential ID. |
