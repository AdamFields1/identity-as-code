# stacks/entra-aws-federation

The deployable unit that makes an Entra tenant the identity source for AWS IAM
Identity Center. It calls `modules/entra/aws-identity-center-app` once per target
from a map, in one plan and one state file. In this repository the corp tenant has
two targets, `commercial` and `govcloud`, because those are two partitions with
two Identity Center instances that cannot share an identity source configuration.

Tenant cells under `tenants/azure/<tenant>/entra-aws-federation/` point at this
stack and provide values only. Only corp has such a cell: the subsidiary's users
reach AWS through corp groups, and there is no subsidiary Identity Center.

## The model

```
aws_groups (one list, in the cell)
  AWS-COM-111111111111-PlatformAdmin  --+
  AWS-COM-222222222222-PowerUser      --+--> commercial gallery app --SCIM--> commercial identity store
  AWS-GOV-111111111111-PlatformAdmin  --+
  AWS-GOV-333333333333-ReadOnly       --+--> govcloud gallery app   --SCIM--> govcloud identity store
```

Every group is named `AWS-<PARTITION>-<accountId>-<PermissionSetName>`. The stack
hands each target the groups whose `PARTITION` matches the target's
`partition_token`, so a group is listed once and its name decides which
application it is assigned to and therefore which instance it is provisioned
into. The AWS cell for that instance (`tenants/aws/<target>/aws-identity-center`)
lists the same names and parses them into account assignments. Membership is
Entra's, including PIM for groups where activation should be just in time. See
[ADR 0008](../../docs/adr/0008-entra-id-as-the-identity-source-for-aws.md).

The two lists (this cell's `aws_groups` and each AWS cell's `group_display_names`)
are kept in step by review, not by code: they live in different trees with
different state backends and different credentials, and a Terragrunt dependency
across clouds is exactly the coupling ADR 0004 declined. A group in one list and
not the other is caught at plan time either way: missing here, the AWS cell's
group lookup fails; missing there, the group is provisioned but grants nothing,
which the AWS cell's reviewer sees as an unreferenced identity store group.

## Why one stack with a map, not one cell per instance

The two applications share nothing at runtime, so two cells would be defensible.
They share a review, though: the question "who can reach AWS at all" is answered
by `aws_groups`, and a reviewer should see the whole list in one plan. The targets
also share the one manual dependency (the tenant's federation metadata) and the
one secret source (`TF_VAR_scim_credentials`). One cell, one map, one state file
keeps that whole surface in one place.

## Secrets

SCIM credentials never appear in a cell, a module, or a generated file. They arrive
as `TF_VAR_scim_credentials`, a map keyed like `targets`:

```bash
export TF_VAR_scim_credentials='{
  commercial = { base_address = "https://scim.us-east-1.amazonaws.com/CHANGEME/scim/v2", secret_token = "CHANGEME" }
  govcloud   = { base_address = "https://scim.us-gov-west-1.amazonaws.com/CHANGEME/scim/v2", secret_token = "CHANGEME" }
}'
```

In CI that value is a GitHub environment secret named `SCIM_CREDENTIALS`, exposed
to the job as `TF_VAR_scim_credentials`. The Azure workflows in this repository do
not map it yet; until they do, this cell is planned and applied from a workstation
with `az login`, and the wiring is listed as follow-up work in ADR 0008.

A target with `scim.enabled = true` and no entry in the map fails the plan with a
message naming the target. A target with `scim.enabled = false` is the state to
apply first, before the AWS console has issued a token (module README, ordering).

What the provider does with the values: `azuread_synchronization_secret` writes
them to the service principal and keeps them in state. They are therefore in the
state blob and in any saved plan file. The state container is Entra-authenticated
with no shared keys (ADR 0004), plan artifacts have a retention period, and the
token is rotated from the AWS console when either of those is a concern.

## Ordering with the AWS cells

1. Apply this cell with `scim.enabled = false` for a new target.
2. Finish the AWS console steps (module README): change identity source, upload
   metadata, enable automatic provisioning, copy the endpoint and token.
3. Export `TF_VAR_scim_credentials`, set `scim.enabled = true`, apply again.
4. Wait for the first provisioning cycle, then plan the AWS cell for that target.
   Its group lookups fail until SCIM has created the groups, which is the intended
   guard against assigning a permission set to a group that does not exist.

## Provider configuration

`versions.tf` declares `required_providers` only. The `provider "azuread"` and
`provider "azurerm"` blocks are generated by Terragrunt (`tenants/azure/root.hcl`),
which supplies `tenant_id` and `subscription_id` from `ARM_TENANT_ID` and
`ARM_SUBSCRIPTION_ID` so no tenant cell contains a GUID. Both providers
authenticate with OIDC. `subscription_id` is accepted but unused by this
Entra-only stack. The identity running the apply needs
`Application.ReadWrite.All`, `AppRoleAssignment.ReadWrite.All`,
`Synchronization.ReadWrite.All`, and `Group.Read.All`, or the Cloud Application
Administrator role.

## Standalone use without Terragrunt

```hcl
provider "azuread" {
  tenant_id = "00000000-0000-0000-0000-000000000000"
  use_oidc  = true
}

module "entra_aws_federation" {
  source = "./stacks/entra-aws-federation"

  tenant_id = "00000000-0000-0000-0000-000000000000"

  aws_groups = [
    "AWS-COM-111111111111-PlatformAdmin",
    "AWS-COM-111111111111-ReadOnly",
  ]

  targets = {
    commercial = {
      display_name    = "AWS IAM Identity Center (commercial)"
      partition_token = "COM"
      identifier_uris = ["https://us-east-1.signin.aws.amazon.com/platform/saml/d-0000000000"]
      reply_urls      = ["https://us-east-1.signin.aws.amazon.com/platform/saml/acs/d-0000000000"]
      sign_on_url     = "https://d-0000000000.awsapps.com/start"
    }
  }

  # scim_credentials comes from TF_VAR_scim_credentials.
}
```

## Inputs

| Name | Type | Description |
|------|------|-------------|
| `tenant_id` | `string` | Entra tenant ID. |
| `subscription_id` | `string` | Accepted for the generated azurerm provider; unused here. |
| `aws_groups` | `list(string)` | Every convention-named AWS access group, listed once. |
| `targets` | `map(object)` | Identity Center instances keyed by partition name, each with a `partition_token`. |
| `scim_credentials` | `map(object)`, sensitive | `{ base_address, secret_token }` per target, from the environment. |

## Outputs

| Name | Description |
|------|-------------|
| `targets` | Key to `{ client_id, service_principal_object_id, app_role_id, signing_certificate_thumbprint, synchronization_job_id }`. |
| `federation_metadata_urls` | Key to the metadata URL for the AWS console wizard. |
| `assigned_groups` | Key to the group names handed to that target. |
| `assigned_group_ids` | Key to `{ group display name => object ID }`. |
