# stacks/entra-conditional-access

The deployable unit for a tenant's Conditional Access baseline. It composes the
`conditional-access` module, which creates named locations, custom authentication
strengths, and policies in one plan and one state file.

Tenant cells under `tenants/azure/<tenant>/entra-conditional-access/` point at this
stack and provide values only. Both `corp` and `subsidiary` have a cell; the
subsidiary enforces the legacy authentication block while corp still runs it in
report-only.

## The two rules this stack cannot break

1. **Every policy excludes the break-glass group.** `break_glass_exclusion_group` is
   required, non-empty, and appended to every policy by the module. There is no flag
   to opt a policy out. See
   [ADR 0007](../../docs/adr/0007-break-glass-exclusion-is-mandatory.md).
2. **Policies are not destroyed by accident.** `prevent_destroy` is set on every
   policy. Removing one is an explicit lifecycle edit that shows in review.

## Report-only first

`state` defaults to `enabledForReportingButNotEnforced`. The sign-in log then shows
which sign-ins a policy would have affected. Promoting to `enabled` is a one-word
change in the tenant cell. The sample set in the tenant cells shows both: the
risk-based policy stays report-only in every tenant, the MFA policy is enforced in
every tenant, and the legacy authentication block is enforced in the subsidiary and
report-only in corp.

## Cross-stack references

Policies scope to groups by display name. The privileged-group policy references
groups created by `stacks/entra-pim-governance`, so that stack is applied first. A
missing group fails the plan with the group name in the error. The reference is by
name rather than by Terragrunt `dependency` output on purpose: the Conditional Access
stack should be plannable against a tenant whose PIM groups were created by hand,
and a name is what a reviewer can check in the portal.

## Provider configuration

`versions.tf` declares `required_providers` only. The `provider "azuread"` and
`provider "azurerm"` blocks are generated by Terragrunt (`tenants/azure/root.hcl`),
which supplies `tenant_id` and `subscription_id` from `ARM_TENANT_ID` and
`ARM_SUBSCRIPTION_ID` so no tenant cell contains a GUID. Both providers
authenticate with OIDC. `subscription_id` is accepted but unused by this
Entra-only stack.

## Standalone use without Terragrunt

```hcl
provider "azuread" {
  tenant_id = "00000000-0000-0000-0000-000000000000"
  use_oidc  = true
}

module "entra_conditional_access" {
  source = "./stacks/entra-conditional-access"

  tenant_id                   = "00000000-0000-0000-0000-000000000000"
  break_glass_exclusion_group = "SEC Break Glass Accounts"

  named_locations = {
    corp-egress = {
      display_name = "Corporate egress"
      ip_ranges    = ["203.0.113.0/24"]
      trusted      = true
    }
  }

  policies = {
    require-mfa-all-users = {
      display_name   = "CA003 Require MFA for all users"
      state          = "enabled"
      users          = { included_users = ["All"] }
      locations      = { included = ["All"], excluded = ["corp-egress"] }
      grant_controls = { built_in_controls = ["mfa"] }
    }
  }
}
```

## Inputs

| Name | Type | Description |
|------|------|-------------|
| `tenant_id` | `string` | Entra tenant ID. |
| `subscription_id` | `string` | Accepted for the generated azurerm provider; unused here. |
| `break_glass_exclusion_group` | `string` | Emergency access group display name. Required. |
| `named_locations` | `map(object)` | Locations keyed by logical name. |
| `authentication_strengths` | `map(object)` | Strengths keyed by logical name. |
| `policies` | `map(object)` | Policies keyed by logical name. |

## Outputs

| Name | Description |
|------|-------------|
| `named_location_ids` | Key to named location object ID. |
| `authentication_strength_ids` | Key to strength policy ID. |
| `policies` | Key to `{ object_id, display_name, state }`. |
| `break_glass_group_id` | Object ID of the exclusion group. |
