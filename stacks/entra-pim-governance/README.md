# stacks/entra-pim-governance

The deployable unit for privileged access in an Entra tenant. It composes three
modules, in order, into one plan and one state file:

1. `security-group` creates role-assignable groups. `assignable_to_role` is forced
   to `true` by the stack; that is the whole point of these groups.
2. `pim-role-policy` sets the activation, eligibility, and assignment rules for each
   group's member role.
3. `pim-eligibility` makes each group eligible for a directory role and makes people
   or groups eligible for membership.

Tenant cells under `tenants/azure/<tenant>/entra-pim-governance/` point at this stack
and provide values only. The subsidiary is stricter: PT2H activation and approval
required for every group.

## The model

```
person  --eligible for-->  PIM group  --eligible for-->  directory role
             (hop 1)                       (hop 2)
```

Nobody holds a standing directory role. Activating hop 1 is governed by the group's
role management policy (MFA, justification, optional approval, PT4H cap). Hop 2 is
activated through PIM for roles. The break-glass accounts are the only exception and
they are outside this stack entirely.

## Why one stack

An eligibility granted before its policy exists activates under Entra's permissive
defaults until the next apply. A policy cannot exist before its group. `depends_on`
between the three modules makes Terraform sequence them, and one state file means one
plan shows the whole privileged-access posture. Splitting this into three stacks
would make the ordering a runbook instead of a graph.

## What this stack refuses

- A role policy or eligibility that targets a group not defined in
  `privileged_groups`. This stack governs only the groups it creates.
- Listed membership. Membership of a PIM group is written by activation. The
  security-group module leaves `members` null when nothing is listed.
- `require_approval` without an approver group.
- Durations that are not ISO 8601.

## Provider configuration

`versions.tf` declares `required_providers` only. The `provider "azuread"` and
`provider "azurerm"` blocks are generated by Terragrunt (`tenants/azure/root.hcl`),
which supplies `tenant_id` and `subscription_id` from `ARM_TENANT_ID` and
`ARM_SUBSCRIPTION_ID` so no tenant cell contains a GUID. Both providers
authenticate with OIDC. `subscription_id` is accepted but unused by this
Entra-only stack. The identity running the apply needs Privileged Role
Administrator to create role-assignable groups and to write role eligibilities.

## Standalone use without Terragrunt

```hcl
provider "azuread" {
  tenant_id = "00000000-0000-0000-0000-000000000000"
  use_oidc  = true
}

module "entra_pim_governance" {
  source = "./stacks/entra-pim-governance"

  tenant_id = "00000000-0000-0000-0000-000000000000"

  privileged_groups = {
    pim-global-admin = {
      display_name = "PIM Global Administrators"
      owners       = ["iam.lead@corp.example.com"]
    }
  }

  role_policies = {
    global-admin-member = {
      group_display_name = "PIM Global Administrators"
      activation = {
        maximum_duration = "PT2H"
        require_approval = true
        approver_groups  = ["SEC IAM Approvers"]
      }
    }
  }

  directory_role_eligibilities = {
    global-admin = {
      role_display_name  = "Global Administrator"
      group_display_name = "PIM Global Administrators"
    }
  }

  group_eligibilities = {
    iam-lead-global-admin = {
      group_display_name = "PIM Global Administrators"
      principal_user     = "iam.lead@corp.example.com"
    }
  }
}
```

## Inputs

| Name | Type | Description |
|------|------|-------------|
| `tenant_id` | `string` | Entra tenant ID. |
| `subscription_id` | `string` | Accepted for the generated azurerm provider; unused here. |
| `privileged_groups` | `map(object)` | Role-assignable groups keyed by logical name. |
| `role_policies` | `map(object)` | Activation and assignment rules keyed by logical name. |
| `directory_role_eligibilities` | `map(object)` | Group to directory role eligibilities. |
| `group_eligibilities` | `map(object)` | Person or group to PIM group eligibilities. |

## Outputs

| Name | Description |
|------|-------------|
| `group_ids` | Group key to object ID. |
| `role_policy_ids` | Policy key to role management policy ID. |
| `directory_role_eligibility_ids` | Key to schedule request ID. |
| `group_eligibility_ids` | Key to eligibility schedule ID. |
| `role_template_ids` | Role display name to template ID. |
